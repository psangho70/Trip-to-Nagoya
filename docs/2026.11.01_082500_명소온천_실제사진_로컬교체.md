## 2. 작업 계획 (원인 분석 및 해결 방안)

### 2.1 반복된 이미지 불일치의 핵심 원인 (Root Cause)
1. **외부 위키미디어(Wikimedia Commons) 핫링크 차단 및 429/404 오류**:
   - `commons.wikimedia.org/wiki/Special:FilePath/...` 형태의 외부 이미지 URL이 브라우저 동시 요청 시 **HTTP 429 (Too Many Requests)** 속도 제한에 걸리거나 리다이렉트 대상 파일이 존재하지 않아 로딩에 실패했습니다.
2. **잘못된 `onerror` 대체 이미지(Fallback) 설정**:
   - `app.js` 내 이미지 태그(`<img>`)에 `onerror="this.src='.../Nagoya_Castle(Edit2).jpg'"` 코드가 하드코딩되어 있어, 외부 이미지 로딩이 실패할 때마다 온천(`#yukichiro` 등)이나 다른 명소의 사진이 강제로 **'나고야성 천수각'** 사진으로 바뀌어 표시되는 현상이 발생했습니다.
3. **일부 부정확한 외부 파일명 매칭**:
   - 타이코 천연온천 유키치로 등에 실제 온천 사진 대신 나카가와 운하 항공사진(`Nakagawa_Canal.jpg`) 등이 연결되어 있었습니다.

### 2.2 해결 계획
1. **공식 사이트 및 공식 관광청의 실제 현장 사진 42장 전수 로컬 다운로드 (`images/` 폴더)**:
   - 각 명소·온천·쇼핑몰·맛집의 일본 공식 홈페이지(`nagoyajo.city.nagoya.jp`, `toukichirou.com`, `canalresort.jp`, `nagashima-onsen.co.jp`, `sakaepark.co.jp`, `houraiken.com`, `yabaton.com`, `komeda.co.jp`, `tori-kai.com`) 및 아이치현·나고야시·미에현 공식 관광 포털(`aichinow.pref.aichi.jp`, `nagoya-info.jp`, `kankomie.or.jp`)에서 실제 현장 사진을 `c:\Antigravity\Trip to Nagoya\images\` 폴더에 직접 저장합니다.
2. **42장 전체 이미지 육안 검수**:
   - 다운로드된 모든 이미지 파일을 직접 열람하여 캡션 설명과 실제 사진이 100% 일치하는지, 중복 사진이 없는지 전수 확인합니다.
3. **나고야성 강제 대체(`onerror`) 제거 및 URL 해시(`#yukichiro` 등) 직접 접속 지원**:
   - `app.js`에서 `Nagoya_Castle(Edit2).jpg` 대체 스크립트를 완전히 제거하고, 페이지 새로고침 시 URL 해시(`#yukichiro`, `#nagoya-castle` 등)를 인식해 해당 상세 페이지를 즉시 열도록 개선합니다.

### 3.2 코드 및 서버 개선 내역
- `app.js`:
  - 42개 이미지 경로를 모두 로컬 `images/...` 경로로 교체하여 외부 서버 장애나 속도 제한(429) 없이 즉시 표시되도록 수정.
  - `onerror` 시 나고야성 사진으로 강제 치환하던 코드 완전 삭제.
  - 갤러리 상단 `🔍 터치하여 크게 보기` 배지 및 각 사진 클릭 시 모달 확대 보기가 즉시 작동하도록 개선.
  - 브라우저 새로고침 시 URL 해시(`#yukichiro`, `#nagoya-castle` 등)를 읽어 해당 상세 페이지로 바로 이동하도록 개선.
- `server.js`:
  - 로컬 이미지 서빙을 위한 MIME 타입(`.webp` 포함) 지원 추가 및 웹 서버 재시작 완료.
