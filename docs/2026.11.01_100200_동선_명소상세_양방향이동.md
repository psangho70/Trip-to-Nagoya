# 4일 동선과 명소/온천 상세 페이지 간 양방향 이동 및 복귀 기능 구현

## 실행을 명령받은 프롬프트
> 1. "4일 동선"에 표현된 장소가 "명소/온천" 페이지에 등록되어 있는 장소이면, 
> 바로 "4일 동선" 페이지에서 해당 "명소/온천" 상세 페이지로 이동할 수 있는 기능을 만들어 주세요. 
> 이전 "4일 동선" 페이지의 해당위치로 돌아올 수 있는 기능과 함께 만들어 주세요.

---

## 1. 작업 계획
1. **4일 동선 항목과 16개 명소/온천 데이터 매핑 (`itineraryData` ➔ `placesData`)**:
   - 4일간의 총 34개 일정 중 명소, 온천, 쇼핑, 미식에 해당하는 20개 일정 항목에 `placeId` 속성을 정확히 매칭.
2. **4일 동선 카드 내 상세 페이지 바로가기 버튼 제공**:
   - 일정 카드 상단 헤더에 `[♨️ 상세 정보 ❯]` 배지 버튼 추가.
   - 카드 하단 액션 버튼 영역에 `[♨️ 명소 상세 & 실제 사진 보기 ❯]` 버튼 추가.
   - 각 타임라인 카드에 고유 ID(`step-${containerId}-${idx}`) 부여.
3. **이전 동선 위치 기억 및 완벽한 복귀 로직 (`timelineReturnContext`)**:
   - 사용자가 "4일 동선"에서 상세 보기 버튼을 클릭했을 때, 현재 일차(`dayNum`)와 카드 ID(`stepId`)를 기록하고 상세 페이지로 이동.
   - 상세 페이지 상단/하단 뒤로가기 버튼의 문구를 `‹ {dayNum}일차 동선으로 돌아가기 (방금 보던 위치)`로 동적 전환.
   - 뒤로가기 클릭 시 4일 동선 탭 및 해당 일차 탭을 자동 활성화하고, 방금 보던 카드 위치로 부드럽게 스크롤(`scrollIntoView({ behavior: 'smooth', block: 'center' })`)하며, 펄스 하이라이트 애니메이션(`step-highlight-pulse`)을 주어 보고 있던 위치를 즉시 인지하도록 구현.

## 2. 작업 진행 및 조치 결과
1. **`app.js` 데이터 및 로직 수정**:
   - `itineraryData`의 1일차~4일차 총 20개 방문지 일정에 해당하는 `placeId`를 100% 매핑 완료.
   - `renderTimeline`: 각 카드에 고유 ID 부여 및 장소 등록 여부에 따른 상세 이동 버튼 렌더링.
   - `goToPlaceDetailFromTimeline`: 클릭한 일정의 일차와 카드 ID를 기록하고 상세 뷰로 전환.
   - `closePlaceDetail`: 동선에서 진입한 경우 해당 일차 탭을 열고 원래 보던 카드로 부드럽게 스크롤 복귀 및 펄스 강조 효과 적용. 일반 목록 진입 시에는 기존 목록 뷰로 복귀.
2. **`index.html` 수정**:
   - 상세 뷰 상단 뒤로가기 버튼(`btn-detail-back`)에 id를 부여하여 복귀 대상에 따라 문구와 스타일이 동적으로 변경되도록 보강.
3. **`styles.css` 스타일 추가**:
   - `.step-spot-badge-btn`, `.btn-spot-detail`: 타임라인 카드 내 고급스러운 블루 그라데이션 상세 보기 버튼.
   - `.step-highlight-pulse`: 복귀 시 해당 카드가 은은한 푸른빛으로 깜빡여 사용자가 보고 있던 위치를 바로 확인할 수 있는 펄스 애니메이션.
   - `.timeline-return-mode`: 상세 페이지 뒤로가기 버튼이 동선 복귀 모드일 때의 시인성 강조 스타일.
4. **Git 커밋 및 GitHub 원격 저장소(`main`) 푸시**:
   - 변경 사항을 커밋하고 GitHub에 푸시하여 실시간 웹서비스([https://psangho70.github.io/Trip-to-Nagoya/](https://psangho70.github.io/Trip-to-Nagoya/))에 즉시 자동 배포 반영.
