# ✈️ 나고야 3박 4일 성인 4인 가족 여행 가이드 웹서비스 (Trip to Nagoya)

> **여행 기간**: 2026년 12월 26일(토) ~ 12월 29일(화) (3박 4일)  
> **여행 인원**: 성인 4인 가족 맞춤 (이동 시간 및 보행 피로도 최소화 동선)  
> **웹서비스 바로가기 (GitHub Pages)**: [https://psangho70.github.io/Trip-to-Nagoya/](https://psangho70.github.io/Trip-to-Nagoya/)  
> **저장소 주소**: [https://github.com/psangho70/Trip-to-Nagoya](https://github.com/psangho70/Trip-to-Nagoya)

## 🛠️ 2. 단계별 개발 과정 (Development Process)

본 웹서비스는 사용자의 요구사항과 현장 사용성 피드백을 반영하여 총 7단계에 걸쳐 고도화되었습니다. 모든 진행 이력은 `docs/` 폴더 아래에 한국 표준시(KST) 기준 마크다운 문서로 기록되어 있습니다.

### Step 1. 숙박·항공 이미지 바우처 분석 및 개발 계획 수립
- **요구사항**: `일본 숙박.jpg`, `일본 항공권_김한희 1.png`, `일본 항공권_김한희 2.png` 3장의 이미지를 분석하고, 성인 4인 나고야 여행(명소·온천·쇼핑 중심) 모바일 웹 가이드 개발 계획서 작성.
- **구현 내용**:
  - 이미지 판독을 통해 출국(제주항공 7C 1602, 인천 T1 ➔ 나고야 T2)과 귀국(진에어 LJ 0294, 나고야 T1 ➔ 인천 T2)의 **터미널 교차 위험 요소**를 도출.
  - 숙소(`APA 호텔 나고야 에키마에 미나미`)가 나고야역 서쪽 태합통구 도보 5분 거리임을 확인하고, 백화점·지하상가·빅카메라·온천 셔틀버스를 연계한 거점형 동선 설계.

### Step 2. 여행 경험자 후기 기반 피로 최소화 동선 및 웹서비스 구축
- **요구사항**: 나고야 실제 여행자들의 체험 정보를 반영하여 이동 시간 소비와 보행 피로가 최소화된 출발~도착 상세 동선(방문지·식사·이동 방법·비용 포함) 구현.
- **구현 내용**:
  - **4인 가족 택시 적극 활용 전략**: 일본 기본요금 약 ¥500 및 나고야 도심 주요 명소 간 ¥1,400~¥1,800(1인당 약 ¥400)으로 지하철 환승 계단 없이 문 앞까지 이동하는 동선 수립.
  - **아츠타 호라이켄 대기 0분 전략**: 진구마에역 도착 직후(09:40) 식당 입장 번호표를 먼저 수령한 뒤 아츠타 신궁 평지 숲길을 산책하는 실전 팁 반영.
  - **나고야성 연말 휴관(12/29~31) 회피**: 나고야성을 2일차(12/27 일요일) 오전에 배치하고 계단이 많은 천수각 대신 평지 실내 관람 코스인 **혼마루 어전** 중심으로 구성.
  - **2일차 온천 A안 / B안 실시간 스위치**: 당일 컨디션에 따라 도심 무료셔틀 15분 **A안(캐널 리조트)**과 대자연 노천탕·일루미네이션 **B안(나가시마 온천 유아미노시마 & 나바나노사토)**을 버튼 하나로 전환할 수 있도록 구현.

### Step 3. 프로젝트 폴더명 영문화 (`Trip to Nagoya`)
- **요구사항**: 작업 폴더명을 `"일본여행"`에서 `"Trip to Nagoya"`로 변경.
- **구현 내용**: 실행 중인 프로세스 잠금을 안전하게 해제한 후 `c:\Antigravity\Trip to Nagoya`로 폴더명을 변경하고 로컬 웹 서버를 재기동.

### Step 4. 택시 기사님 일본어 음성 안내 (Web Speech API TTS) 기능 추가
- **요구사항**: 택시 탑승 시 화면을 보여줄 뿐만 아니라 택시 기사님께 일본어를 오디오 음성으로 직접 들려줄 수 있는 기능 추가.
- **구현 내용**:
  - 브라우저 내장 `window.speechSynthesis` (`ja-JP` 음성 엔진, 차량 내 소음 환경을 고려한 `rate: 0.88` 속도 최적화)를 적용.
  - 각 택시 카드에 정중한 일본어 회화문(예: *"運転手さん、名古屋城の正門、本丸御殿までお願いします。"*)을 매칭하고, **`🔊 기사님께 들려주기`** 버튼 및 어두운 일본어 카드 영역 전체 터치 시 음성이 출력되도록 구현.

### Step 5. 명소·온천·쇼핑·미식 16선 개별 상세 페이지 구현
- **요구사항**: 명소/온천 페이지의 각 방문지를 클릭하면 사진, 특징, 주요 관광 포인트가 정리된 모바일 고시인성 상세 페이지로 이동하는 기능 추가.
- **구현 내용**:
  - 16개 전 방문지(`placesData`)에 대해 **사진 갤러리, 핵심 요약 4대 타일(추천 체류시간·이동 피로도·4인 예상 비용·운영시간), 연말 휴관 알림, 주요 관광 포인트, 피로 최소화 추천 관람 코스, 나고야역 기준 이동 안내 및 일본어 음성 재생 버튼**을 갖춘 상세 뷰(`openPlaceDetail`)와 브라우저 뒤로가기(`History API`) 연동을 완성.

### Step 6. 실제 현장 사진 42장 로컬 호스팅(`images/`) 및 모달·중복 오류 완전 해결
- **요구사항**: 외부 이미지가 실제 명소/온천 사진과 다르거나 중복 표시되고, `"터치하여 크게 보기"` 모달이 동작하지 않는 문제를 점검하여 정확한 실제 현장 사진으로 수정.
- **원인 분석 및 해결**:
  - 외부 위키미디어(`commons.wikimedia.org`) 핫링크가 동시 요청 시 **HTTP 429(속도 제한)** 또는 **404 오류**를 반환하며, `onerror` 시 나고야성 사진으로 강제 대체되던 로직이 원인임을 규명.
  - 각 명소·온천·쇼핑·맛집의 **일본 공식 홈페이지**(`nagoyajo.city.nagoya.jp`, `toukichirou.com`, `canalresort.jp`, `nagashima-onsen.co.jp`, `sakaepark.co.jp`, `houraiken.com`, `yabaton.com`, `komeda.co.jp`, `tori-kai.com`) 및 **공식 관광청 포털**(`aichinow.pref.aichi.jp`, `nagoya-info.jp`, `kankomie.or.jp`)에서 **실제 현장 사진 42장**을 `images/` 폴더에 로컬 저장하고 전수 육안 검수 완료(중복 0건).
  - `onerror` 나고야성 강제 대체 코드를 제거하고, `🔍 터치하여 크게 보기` 배지 및 각 사진 터치 시 모달 확대 보기가 즉시 작동하도록 개선했으며, URL 해시(`#yukichiro`, `#nagoya-castle` 등) 새로고침 시 해당 상세 페이지가 바로 열리도록 라우팅을 보강.

### Step 7. `README.md` 작성 및 GitHub 원격 저장소 백업
- **요구사항**: 전체 개발 과정을 `README.md` 파일로 정리하고 GitHub(`https://github.com/psangho70/Trip-to-Nagoya`)에 백업.
- **구현 내용**: 프로젝트 루트 `README.md` 작성, `Trip to Nagoya` 독립 Git 저장소 구성을 통한 `main` 브랜치 원격 푸시 완료.

### Step 8. GitHub Pages 웹 호스팅 자동 배포 워크플로우 구성
- **요구사항**: GitHub 레파지토리 `Settings > Pages` 설정(`Source: GitHub Actions`)을 점검하고 웹에서 바로 접속 가능한 주소 확인 및 자동 배포 구성.
- **구현 내용**: 사용자가 설정한 `Source: GitHub Actions` 환경에서 별도의 수동 설정 없이 즉시 정적 웹페이지가 빌드·배포되도록 `.github/workflows/static.yml` 및 `.nojekyll` 파일을 구성하여 푸시 완료 ([https://psangho70.github.io/Trip-to-Nagoya/](https://psangho70.github.io/Trip-to-Nagoya/)).

### Step 9. 여행 주의사항 모달 전환 및 큰 글씨 모드 기능 정상화
- **요구사항**: 상단 터미널 주의 배너를 상시 노출하지 않고 처음 실행 시 "여행 주의사항" 팝업 모달로 표시하며, 작동하지 않던 글씨 크기 기능의 의도 설명 및 정상 동작 수정.
- **구현 내용**:
  - 상단 헤더의 상시 배너를 제거하고 첫 실행 시 출국/귀국 터미널 상이 정보와 나고야성 연말 휴관, 택시 팁이 포함된 팝업 모달 창(`notice-modal`)을 자동 띄우도록 개선 ("오늘 하루 보지 않기" 및 상단 헤더/홈 화면에서 언제든 다시 열기 지원).
  - 글씨 크기 모드의 원래 의도(부모님을 위한 모바일 야외 가독성 극대화 1.2배 확대)에 맞추어, 루트 `html` 요소의 폰트 기준(`rem`)이 즉각 확대되도록 CSS 및 자바스크립트를 전면 개선.

### Step 10. 4일 동선과 명소/온천 상세 페이지 간 양방향 이동 및 정확한 위치 복귀 기능 구현
- **요구사항**: "4일 동선"에 표현된 장소가 "명소/온천"에 등록되어 있으면 바로 상세 페이지로 이동하고, 이전 "4일 동선" 페이지의 원래 위치로 정확히 돌아올 수 있는 기능 구현.
- **구현 내용**:
  - 4일간의 총 20개 방문지 일정 카드에 등록된 명소/온천/쇼핑/미식 정보를 100% 매핑하고, 카드 상단 배지 및 하단 액션 바에 `[♨️ 상세 정보 & 실제 사진 보기 ❯]` 버튼을 배치.
  - 상세 이동 시 보던 일차(`dayNum`)와 카드 ID(`stepId`)를 기록하여, 상세 페이지 상·하단 뒤로가기 버튼이 `‹ {dayNum}일차 동선으로 돌아가기`로 자동 전환되도록 구현.
  - 뒤로가기 클릭 시 해당 일차 탭을 열고 방금 보던 카드 위치로 부드럽게 스크롤 복귀(`scrollIntoView`)하며, 펄스 하이라이트 애니메이션(`step-highlight-pulse`)을 주어 보던 위치를 즉시 인지할 수 있도록 완성.

### Step 11. 스마트폰·태블릿·PC 전 디바이스 반응형 UI 및 가로 잘림(오버플로우) 오류 전면 수정
- **요구사항**: 스마트폰 세로보기 환경에서 헤더 버튼의 세로 꺾임 줄바꿈 및 화면 왼쪽이 잘려 나가는 가로 스크롤/오버플로우 문제를 수정하고 전 디바이스 최적화.
- **구현 내용**:
  - `min-width: 0` 및 `overflow-x: hidden` 전역 적용으로 컨테이너 강제 찢김 차단.
  - 상단 헤더 버튼에 `white-space: nowrap !important;` 및 모바일 전용 컴팩트 레이아웃을 적용하여 1줄 가로 정렬 완료.
  - 4일 동선 탭을 `repeat(4, minmax(0, 1fr))`로 개선하여 Day 1~4가 스마트폰 화면에서 온전히 표시되도록 수정.
  - 타임라인 카드 여백 슬림화 및 상세 버튼 100% 풀 너비 터치 최적화, 하단 네비게이션 중앙 정렬 보정.

### Step 12. 4일 동선과 택시 카드 간 맞춤 매핑 및 원래 위치 복귀 기능 구현
- **요구사항**: "4일 동선"의 "택시 카드 보기" 클릭 시 해당 동선에 매칭되는 택시 카드로 이동되고, 내용 확인 후 복귀를 누르면 원래의 "4일 동선" 항목으로 정확히 돌아올 수 있는 상세 이동 기능 구현.
- **구현 내용**:
  - `taxiCardsData` 9종에 고유 식별자(`id`) 부여 및 동선별 맞춤 매칭 함수(`resolveTaxiId`) 제작.
  - 일정 카드의 `택시 카드 보기 🚕` 클릭 시 대상 택시 카드로 직행하여 화면 중앙 스크롤 및 펄스 하이라이트(`step-highlight-pulse`) 처리.
  - 택시 탭 상단 배너 및 카드 내에 `‹ Day X 일정으로 돌아가기 (방금 보던 위치)` 복귀 버튼 제공.
  - 복귀 시 보던 일차(Day 1~4) 탭을 자동 활성화하고 원래 보던 일정 카드로 부드럽게 스크롤 복귀하여 펄스 효과 부여.

## 🚀 5. 로컬 실행 방법

별도의 외부 패키지(`npm install`) 설치 없이 Node.js 기본 내장 모듈만으로 즉시 실행됩니다.

```bash
# 1. 프로젝트 폴더로 이동
cd "Trip to Nagoya"

# 2. 로컬 웹 서버 실행 (기본 포트: 8080)
node server.js
```

- **PC 브라우저 접속**: `http://localhost:8080`
- **스마트폰 접속 (동일 Wi-Fi)**: 터미널에 출력되는 로컬 IP 주소(`http://192.168.x.x:8080`)로 접속
